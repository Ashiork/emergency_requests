## 1\. Словарь терминов

| Термин курса | Термин моей темы | Пояснение |
| --- | --- | --- |
| Ticket | Аварийная заявка | Главный объект: обращение жителя/организации об аварии |
| Site | Объект сети | Справочник: котельная, участок теплосети, ЦТП, насосная |
| User | Пользователь | Диспетчер / бригадир / начальник смены |

## 2\. Сущности и поля

### 2.1. `Site` — объект сети (справочник)

| Поле | Тип | Ключ | Обяз. | Смысл |
| --- | --- | --- | --- | --- |
| `id` | integer | **PK** | да | Машинный идентификатор |
| `name` | char(120) | \- | да | Название объекта, например «Котельная Б», «Теплосеть уч. 3» |

### 2.2. `User` — пользователь системы

| Поле | Тип | Ключ | Обяз. | Смысл |
| --- | --- | --- | --- | --- |
| `id` | integer | **PK** | да | Машинный идентификатор |
| `login` | char(50) | UNIQUE | да | Логин для входа |
| `password` | text | \- | да | Хеш пароля |
| `name` | char(100) | \- | да | Имя |
| `surname` | char(100) | \- | да | Фамилия |
| `patronymic` | char(100) | \- | нет | Отчество |
| `role` | enum | \- | да | `Dispatcher` / `Foreman` / `ShiftChief` |

### 2.3. `Ticket` — аварийная заявка (главный объект)

| Поле | Тип | Ключ | Обяз. | Смысл |
| --- | --- | --- | --- | --- |
| `id` | integer | **PK** | да | Машинный идентификатор, идёт в URL `/api/tickets/{id}` |
| `number` | char(20) | UNIQUE | да | Человеческий номер вида `AVR-2026-0001` |
| `title` | char(80) | \- | да | Заголовок, 5–80 символов |
| `description` | char(500) | \- | да | Описание аварии, 10–500 символов |
| `status` | enum | \- | да | `New` / `InProgress` / `Closed` / `Cancelled` |
| `siteId` | integer | **FK - Site.id** | да | Объект сети из справочника |
| `createdBy` | integer | **FK - User.id** | да | Кто создал заявку (диспетчер) |
| `assignee` | integer | **FK - User.id** | нет | Кого назначили (бригадир). У новой заявки пусто |
| `createdAt` | datetime | \- | да | Дата/время создания (UTC) |
| `updatedAt` | datetime | \- | да | Дата/время последнего изменения |

## 4\. Связи словами

*   **Один** `**Site**` **- много** `**Ticket**`**.** У одного объекта сети может быть много заявок за всё время. У каждой заявки ровно один `siteId`.
*   **Один** `**User**` **создал много** `**Ticket**`**.** Диспетчер фиксирует много обращений; у каждой заявки всегда есть `createdBy`.
*   **Один** `**User**` **может быть назначен на много** `**Ticket**`**.** Бригадир выезжает по многим заявкам. У заявки `assignee` — ноль или один (сразу после создания исполнителя ещё нет).
*   **У заявки ноль или один исполнитель.** Это ключевое отличие от создателя: создатель есть всегда, а исполнителя может не быть.

## 5\. Проверка третьей нормальной формы (3НФ)

Название объекта сети хранится в сущности `Site` один раз. `Ticket` содержит только внешний ключ `siteId`. При переименовании объекта меняется одна строка в `Site`, поэтому текст названия не дублируется в заявках. Аналогично: `role` пользователя и `status` заявки хранятся как короткие коды (ENUM), а не как свободный текст в каждой строке. `number` — это отдельное поле со своим назначением (для людей), оно не подменяет `id` и не дублирует его.
